Concept Kernel Protocol v3.12 docs

CKP Core Ontology v3.12 current

The operating definition of a concept kernel, and the law every kernel is judged against. v3.12 is the v3.11 root carried verbatim, plus a closed delta: signal processing as core mechanics (attributed signals, derived scores, and the seven constants that weigh them, each a bounded law), the kernel's own clock as law, the participation layer between core and one kernel (a named set of kernels that turn together), and affordances that carry their contract as data. The three authoring rules of v3.11 hold unchanged: every constraint is one the gating engine is measured to enforce; no class IRI is the subject of a domain-carrying predicate; every constraint reads only the candidate body plus its stamped parent closure.

Verify it yourself

The surface in force is established by digest, never inferred from a validation report: a validator reports conformance against an empty shapes graph too. Check the bytes, then ask the door what it loaded.

curl -sO https://conceptkernel.org/ontology/v3.12/core.ttl
curl -sO https://conceptkernel.org/ontology/v3.12/core.ttl.wave-3.12-pass-3.sha256
shasum -a 256 -c core.ttl.wave-3.12-pass-3.sha256        # core.ttl: OK

Through the door, surface.grounding reports every graph in a kernel's world on each digest plane, and surface.check compares the surface in force with the digests its epoch sealed. See Epochs, Digests & Proof.

The declared gap

G-1 — cross-node kind integrity carries forward from v3.11. Body locality places one property beyond the instance gate: that a referenced IRI is of the kind the reference intends. The root states the ranges so the check is expressible as a store-level query over sealed rows — served through the door as integrity.check — and declares the gap rather than carrying a constraint that would read as enforcement while refusing valid writes.
